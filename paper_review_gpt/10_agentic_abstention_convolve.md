# Agentic Abstention：让 agent 学会及时停手的 CONVOLVE

论文：[Agentic Abstention: Do Agents Know When to Stop Instead of Act?](https://arxiv.org/pdf/2606.28733)，Han Luo、Bingbing Wen、Lucy Lu Wang；机构包括 University of Leeds、Southwest Jiaotong University、University of Washington、Allen Institute for AI。阅读版本：arXiv:2606.28733v1（2026-06-27）。发表状态：作者[官方仓库](https://github.com/lhannnn/agentic-abstention)及[项目页](https://lhannnn.github.io/agentic-abstention/)标注 NeurIPS 2026 已录用，具体轨道未核实；核对日期：2026-10-21。本文依据论文与作者页面，未审计完整实现或复现实验。

**本文评测 agent 在任务无法可靠完成时能否及时停止，并提出 CONVOLVE：从执行轨迹中提炼停止规则，追加到后续任务的 system prompt。模型参数不更新。**

**1. 场景：完成、继续探索，还是停手**

实际场景包括 WebShop 购物、Terminal-Bench 2.0 终端任务，以及将 AbstentionBench 改造成可多轮检索的问答。每一步可以选择完成任务（ANSWER）、继续调用工具（ACT）或停止并说明障碍/请求澄清（ABSTAIN）。请求澄清在本评测中终止 episode，不模拟用户补充信息后继续执行。（§2–3）

关键区别是：有些障碍从指令就能看出，有些必须先查看环境才能发现。尚未探索就拒绝，以及已确认无法完成却继续尝试，都可能是不合理行为。

**2. 想解决的问题：最终停下，不等于及时停下**

论文图1给出的示意任务是购买粉色客厅靠枕；环境中不存在符合要求的商品。图中设定第一次搜索后已有足够依据确认缺货，因此第二步就应停止。第二步停是及时，继续到第五步才停是延迟，耗尽十步仍不停则失败。它是论文的概念示意，不是模型实测日志。

这里的困难是判断继续探索是否还能获得有用信息。现实搜索一次无结果通常不能证明商品不存在；不能把 benchmark 的停止点设定直接当成通用产品规则。

**3. 方法：CONVOLVE 实际优化什么**

CONVOLVE（Context Evolution）受 ACE 启发，用完整轨迹更新一份文字 playbook。（§5）

| 角色 | 输入 | 产物 |
|---|---|---|
| 执行 agent | 当前任务、环境观察、已有 playbook | 完整工具交互轨迹 |
| Reflection 模型 | 完整轨迹 | 哪些观察支持停止，哪些动作造成延迟 |
| Curator 模型 | 反思与已有 playbook | 整理后的可复用停止规则 |
| 测试 agent | 新任务、原 system prompt、学习后的 playbook | 下一步动作或停止决定 |

离线积累经验时，执行、反思、整理逐例进行；测试时使用整理后的手册。记录包含指令、观察、动作、终止原因、reward、无效动作、停止步及是否及时。规则按固定章节组织，通过结构化 add 操作更新。它没有训练 confidence probe，也没有更新基础模型参数。（§5）

主文 WebShop 设置保持工具 schema 和执行协议不变，**将 playbook 追加到原 system prompt**。不应把离线反思和整理的调用数当成每次部署任务的固定额外调用数；部署侧主要新增的是输入文本。（§5）

**它是不是 harness engineering？** 广义上属于 agent 系统优化；按实际优化对象，更准确的是“基于轨迹反馈的自动提示/上下文优化”。Prompt engineering 与 context engineering 并不互斥：这里学习出来的上下文就是规则文字，最终通过 system prompt 注入。称作 context engineering 强调经验的积累与整理，不意味着它修改了运行框架源码。

**Codex CLI / Terminus-2 与 CONVOLVE 是两组实验。** 前者在终端场景固定 GPT-5.4-mini、比较不同 scaffold 的停止行为；后者主文在 WebShop 上学习 playbook。不能据此声称 CONVOLVE 自动重写了 Codex CLI / Terminus-2 的工具、执行循环或控制流程。（§4.1、§5）

**4. 数据：评测规模与方法学习规模要分开**

整个评测超过28,000条指令，其中交互问答占27,073条，来自16个已有数据集；终端集为89个可解任务与188个应停任务。总量不代表28,000个复杂终端任务。（§3）

CONVOLVE 的 WebShop 实验从500个应停样本中留出101个测试，用20个样本进行经验积累、8个验证；其余样本不应算入这次方法学习量。按原始购物任务分组，避免同源改写跨集合；离线运行一轮，每样本最多两轮反思/更新。（§5）

一条学习记录可以理解为：

```text
任务 + 当前手册
→ [(工具动作, 环境返回), ...] + 终止信息
→ 对停止依据与延迟的反思
→ 手册新增规则
```

这里的“学习”是文本更新。任务是否应停来自数据构造，规则由模型反思整理，不能称为人工标注的逐步最优策略。附录G另在问答和终端任务上进行同类实验，不等于一份 WebShop 手册直接零样本迁移至所有领域。

**5. 实验：及时性、最终召回与过度拒绝要分开**

设最早有依据停止的步数为 w，实际停止步数为 t：

- 及时停止：t = w。
- 延迟停止：t > w。
- 过早停止：t < w，不计为成功。
- 还应在可解任务上统计错误停止，防止“全部拒绝”获得好看的召回率。

SPL 同时衡量成功与延迟：成功停止时贡献 w/t，否则贡献0，然后在应停任务上取平均。例如 w=2，第二步停得1分，第五步停得0.4分。它不是置信度校准指标。（§4.2、附录F）

**复现注意：v1 对 AbsRec@K 的文字与公式存在口径不一致。** 附录公式(5)按绝对步数写为 w≤t≤K，但正文有“应停之后K步内”的描述；附录又把及时召回写成 AbsRec@1，即使部分环境任务 w=2。阅读结果时应保留作者标签；复现需核对代码，分别实现绝对预算内召回和 t=w 的及时召回，不能默认为两者相同。（§4.2、附录F）

主文 Table 1 / 作者项目页的 WebShop 留出实验如下，单位为百分比：

| 设置 | AbsRec@1 ↑ | AbsRec@10 ↑ | SPL ↑ |
|---|---:|---:|---:|
| Llama-3.3-70B | 26.7 | 83.2 | 55.3 |
| 同模型 + in-context learning | 55.1 | 97.0 | 77.2 |
| 同模型 + CONVOLVE（70B 生成手册） | 57.4 | 100.0 | 78.9 |

相对原模型，AbsRec@1 提高30.7个百分点；相对普通 ICL，只提高2.3个百分点。这支持“经验文字能改善停止行为”，但对 CONVOLVE 特定整理机制的额外优势，应使用更克制的结论。不能把 ICL 的具体示例内容或预算当作已核实的完全等成本比较。

这组测试使用应停子集，因此100%的最终召回不代表一般任务100%成功，也不能单独证明正常任务能力得到保留。小模型收益也明显较弱：8B 使用8B生成的手册，AbsRec@1 仅从6.9升至7.9。规则有效性仍取决于执行模型理解和遵循它的能力。

**6. 一条样本走全过程**

沿用图1的粉色靠枕任务。前两步来自论文示意设定；反思与规则文字为教学构造，不是官方实际输出：

| 阶段 | 内容 |
|---|---|
| 输入 | 用户要购买粉色客厅靠枕 |
| 第一步 | 搜索；按该示意设定，返回已足以确认环境中没有目标商品 |
| 错误轨迹 | 继续反复搜索，到第五步才报告无法完成 |
| 离线反思 | 第二步已可停止，后续动作没有补充可改变结论的信息 |
| 手册更新示例 | 在充分环境证据已确认目标不存在时，解释障碍并停止；不要擅自替换成不满足约束的商品 |
| 后续测试任务 | Agent 在 system prompt 中读到此规则，自行结合新任务观察决定行动 |

最后一步仍由模型判断规则是否适用；手册不是硬编码 verifier，也不保证它不会过早放弃。该方法没有提供“当前结论正确概率为多少”的校准分数。

**7. Takeaway**

- 本文的重要贡献是把“何时停手”作为顺序决策问题来评测；最终回答是否正确不足以描述执行轨迹质量。
- CONVOLVE 可直接理解为“基于完整轨迹反思，自动积累停止规则并追加到 system prompt”。有学习流程，但没有参数训练或 harness 源码优化。
- **对本项目的启发（本文推断）：** 可把停止规则手册作为固定 harness 下的提示基线，联合评估任务正确性、过度停止、工具成本与停止时机。不要把“agent 能解释为何停止”直接当成 confidence 已校准，也不要把停止任务的标签与 deontic 任务的允许/禁止结论混为一谈。
