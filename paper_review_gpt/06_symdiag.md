# SymDiag：把推理链编译成程序，定位错误并给出反例

论文：[SymDiag: Explainable Diagnosis for LLM Reasoning via Neuro-Symbolic Verification](https://arxiv.org/pdf/2608.08786v1)，Wenyao Cui 等；阅读版本为 arXiv v1（2026-08-09）。已发表于 **KDD 2026 Research Track**，论文集 V.2；[会议官方列表](https://kdd2026.kdd.org/papers/)与 [ACM DOI](https://doi.org/10.1145/3770855.3818004)已核对，日期：2026-10-05。

**这篇做的是推理链的“查错—修复”：让强 LLM 把已有 CoT 翻译成 Prolog，用符号执行找出错误及证据，再让原模型修改推理。** 它没有训练新模型。

**1. 场景：谁检查谁**

输入是“题目、可选背景、模型已经生成的 CoT 和最终答案”。实验包括数学、逻辑、科学和知识问答。

| 角色 | 实际工作 |
|---|---|
| 答题模型 | Llama-3.2-1B、Qwen3-1.7B/8B、GPTOSS-20B，产生和修改 CoT |
| 诊断模型 | 默认 GPTOSS-120B，生成符号程序、审计翻译、组织反馈 |
| SWI-Prolog | 执行形式化检查，返回失败或反例 |

输出包括失败步骤、错误类型、证据和修改范围。这里的 *faithful* 主要指文本推导成立；实验没有验证 CoT 是否真实反映模型内部产生答案的因果过程。（§3.1、§4.1.3）

**2. 想解决的问题：告诉模型“错了”，还缺什么**

论文图2中，一道求最小整数的题，原 CoT 声称“最小值是151”。但110也满足题目条件，而且更小。诊断应告诉模型：**最小性结论被110这个反例推翻，应补查遗漏候选。**

最终答案对错不能直接定位推导漏洞；答案碰巧正确时，还可能掩盖中间错误。作者要输出可检查的错误证据，让后续修改有具体依据。（§1、图2）

**3. 方法：先查翻译，再查推理**

流程分为诊断和修复两阶段。（[§3，PDF第4–5页](https://arxiv.org/pdf/2608.08786v1#page=4)）

1. **生成两套 Prolog。** A分支直接翻译题目与CoT；B分支先把每步改写得更严格，显式写出范围和隐含假设，再翻译。每步记录已有前提/事实、本步推断、约束条件。
2. **审计翻译。** 先检查语法、类型、变量绑定等；Self-Auditor再比较两支的事实、约束和推断目标。若保持原文含义的最小改写能消除失败，就归为 `TranslationError`，修正编码；否则继续检查推理问题。两支一致也可能一起译错，这套审计不是语义等价证明。
3. **逐步做符号检查。** 一致性检查问“条件会不会互相矛盾”；蕴含检查问“能否找到满足已有前提、却推翻本步结论的赋值”。找到后者就是反例。至少一个获审计批准的分支全部步骤通过，整条CoT才被判为faithful。
4. **把证据交给原模型修复。** 返回“失败位置＋类型＋证据＋局部/全局修改范围”。局部算错就补该步；早期缺前提影响后文，就从最早失败处重写，再检查。默认最多4轮。

所有模型参数不更新，也不提取hidden state或特定token。开销来自两路翻译、审计、符号执行和重复生成；v1没有给出完整调用次数及token/时延账单。

**4. 数据：43.8万条语料，240条核心评测**

**不涉及参数训练。** 作者构建了437,792条记录：先采样CoT和答案，答错的直接标为unfaithful；答对的再经多个judge投票筛选faithful轨迹。这个数量不能当成独立题目数。

一条记录可理解为：`题目＋CoT＋模型答案＋轨迹标签`。它是评测材料，不是本文用于训练LLM的监督记录。

核心实验从中人工审核240条：136条faithful，104条unfaithful；后者含44条答案错误、60条答案正确但推导有错。每个benchmark取30条。v1未交代完整人工标注协议、标注者一致性或独立开发集设置。（[§3.4、图3](https://arxiv.org/pdf/2608.08786v1#page=5)）

**5. 实验：能识别多少错误，反馈能否改善答案**

八个benchmark为：AIME24/25、MATH（数学），AR-LSAT、Logical Deduction（逻辑），GPQA（科学），MMLU/MMLU-Pro（知识与综合推理）。这里测的是这些任务产生的CoT是否有效。

[Table 1](https://arxiv.org/pdf/2608.08786v1#page=7)报告轨迹二分类F1，越高越好；它综合精确率和召回率，不是答题准确率或置信度校准指标。

| 方法 | 反馈内容 | Overall F1（%） |
|---|---|---:|
| Answer Matching | 对照标准答案，返回对/错 | 57.7 |
| LLM-as-Judge | 多judge聚合、自然语言意见 | 62.8 |
| Reward Model | NVIDIA奖励模型的分数 | 57.0 |
| LogicReward | 逻辑奖励及Isabelle证明器信息 | 66.9 |
| SymDiag | 步骤诊断及可检查证据 | **70.7** |

LLM型诊断组件统一用GPTOSS-120B；奖励模型单独用Qwen-3-Nemotron-32B-Reward。作者称多judge使推理预算可比，但未提供完整成本对账。

**不是每组都最好：MMLU-Pro上SymDiag为50.0，低于LLM-as-Judge的54.0。** 去掉Self-Auditor后总体F1降至61.4，去掉逐步符号验证降至60.2（图5）。图4的修复曲线显示最多4轮内答案准确率改善，但未清楚交代跨模型/重复运行如何聚合。F1正类及平均方式也未明确，不能只凭图认定统计显著。

**6. 一条样本走全过程**

以下使用**论文图2的实际示例**，简化转述其流程；任务要求不是作者完整prompt，原文未给出完整模板。

题目：找最小素数 $p$，使某个正整数 $n$ 满足 $p^2\mid n^4+1$；再求满足同一条件的最小正整数 $m$。

| 阶段 | 输入或输出 |
|---|---|
| 原CoT | 得到 $p=17$，最终错误地宣称 $m=151$ 最小 |
| 翻译要求 | 将各步形式化；另一路严格检查“最小”意味着什么 |
| 关键程序检查 | 枚举 $1\le m<151$，测试 $(m^4+1)\bmod289=0$ |
| 求解器返回 | 找到 $m=110$，推翻最小性结论 |
| 诊断反馈 | 指出最小性验证不完整，附上110这个证据 |
| 图中修复CoT | 补全模17剩余类，得到候选110、134、155、179，取110 |

本报告另用整数计算核验了这四个模289解；$151^4+1$ 除以289余34，也不满足整除。图2反馈框把模数写成17，本文按题意及图中程序使用289。

**7. Takeaway**

- **值得借鉴的是反馈结构：失败步骤＋错误类型＋可重算证据。** 实验证据主要来自240条人工审核轨迹，不能据此认定已能可靠验证任意agent轨迹。
- **求解器只保证对编码后的条件负责。** 翻译遗漏规则时，程序跑通也不代表原推理正确；完整prompt、审计阈值及一般蕴含检查的实现仍不够明确。
- **对本项目的启发（本文推断）：** 可将缺失前提、规则冲突、反例等诊断作为trajectory confidence的特征，再用答案正确性标签校准。本文没有完成这一步，也没有验证拒答成本收益。另需注意：图2的反例110恰好就是答案，单个例子的修复成功不能独立证明模型学会了更好的推理。
